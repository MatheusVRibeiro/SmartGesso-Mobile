# SmartGesso Mobile — Contexto Hermes (.hermes.md)

> App mobile (Expo/React Native) do SaaS SmartGesso — operação de campo para gesseiros: orçamentos, serviços, financeiro, estoque, compras, metas; em desenvolvimento ATIVO.

## Stack Tecnológica

| Camada | Tecnologia |
|--------|-----------|
| Runtime | Expo SDK 57 (React Native 0.86.2, React 19.2.3) |
| Framework | expo-router ~57 (rotas em `app/`), TypeScript ~6.0 (strict) |
| Estado/Dados | Zustand (sessão) + TanStack Query (server state) + Axios (client com fila de refresh) |
| Validação | Zod 3 + React Hook Form |
| Tokens | expo-secure-store (nativo) / localStorage (web) — NUNCA AsyncStorage |
| Testes | Jest 29.7.0 + jest-expo 57 + RNTL 14 + `@react-native/jest-preset`; Playwright (E2E web) |
| Build | EAS (eas.json; `app.json` estático — `app.config.ts` quebra no Node 20) |

### ⚠️ Pitfalls de teste (Expo SDK 57 / Jest 29 / OneDrive)

- **Jest 29.7.0 é obrigatório** — Jest 30 é incompatível com jest-expo 57 (`clearMocksOnScope is not a function`).
- **Comando canônico de teste**: `NODE_ENV=test node node_modules/jest/bin/jest.js --silent` (jest local direto). `npx jest` cru pode puxar jest do cache npx (versão errada, erros ESM falsos); `npm test` pode falhar no OneDrive se o jest não estiver materializado — se voltar a funcionar, usar de novo.
- **RNTL v14**: `renderHook` e `act` são **async** (await obrigatório); preset `@react-native/jest-preset` (RN 0.86+); `NODE_ENV=test` forçado no topo do `jest.config.js` (RNTL usa `React.act`, só existe no build de dev).
- **ESLint do repo quebra em qualquer arquivo** (ESLint 10 + eslint-plugin-react 7.37.5 — `contextOrFilename.getFilename is not a function`, pré-existente). Verificação canônica: `npm test` + `npx tsc --noEmit` (filtrando erros pelos seus arquivos).
- **npm no OneDrive não materializa pacotes/binários**: instalar em `/tmp` e copiar para `node_modules/`; manter stashes em `/tmp` (OneDrive pode re-apagar jest/RNTL no meio da sessão).
- **Cópia de verificação fora do OneDrive**: para instalação/teste pesados, manter cópia em `C:/Users/xmath/AppData/Local/Temp/` (ex.: `sg-mobile-verify`) — `tar cf - --exclude=node_modules --exclude=.git --exclude=.expo . | tar xf - -C <verify>` + `npm ci --include=dev` na cópia; re-sincronizar a cada mudança.
